Engineering Control Plane

讓「做完了」這句話變貴

ForgePilot 不寫程式，也不取代你的 coding agent。它只做一件事：在證據不足的時候，不讓任何人——包括 agent，包括你自己——宣告工作完成。

01

五歲版本：走廊上的那幾道門

想像一條走廊，走到底就是「這件事做完了」。走廊上有四道門，每一道都需要一張票才打得開，而且票不能自己寫。

沒有這條走廊的時候，事情是這樣的：你請一個很會寫程式的幫手做一件事，它做完跟你說「好了」。你問它測試過嗎，它說測過了。你信了，把它接到下一件事上——然後三天後你才發現，它測的是三個版本以前的程式碼。

它沒有騙你。它只是說了一句沒有成本的話。「做完了」誰都能說，不需要附上任何東西。

ForgePilot 做的事，就是把那句話變得需要附上四張票。

它自己不會寫程式，不會幫你測試，也不會判斷程式碼好不好——那些是你和你的 agent 的事。它只是站在門邊，檢查票，並且在票不齊的時候說出還缺哪一張。

這聽起來很煩。這正是重點。一個從不擋人的流程，跟沒有流程是同一件事。

02

四張票，缺一張就過不去

有人真的看過並且同意

不是自動通過，也不是「沒人反對就算過」。必須有一筆明確記下來的人工審查，寫著誰在什麼時候同意了什麼。

Human Review

測試通過的，是你正在看的那一版

每次驗證都綁死一個 commit。之後只要再改一行，那張票就自動作廢——不是變成警告，是真的不算數。

Evidence · exact revision

沒有懸著沒人決定的問題

遇到不該自己決定的事，就開一道 Gate 把問題記下來。問題還開著，工作就過不去，而且誰都看得見它開著。

Gate

這個目標本身還在進行中

目標被暫停的時候，底下的工作連驗證都不給跑。暫停就該是真的暫停，不是一個沒人理的標籤。

Goal

四張票同時齊了，工作才進入 DONE——而且在同一個瞬間，等著它的下一件工作自動變成可以開始。中間不存在「A 完成了但 B 還沒被通知」的空檔。

03

被擋住的時候，它會說出缺哪一張

最容易讓人愣住的情況是這個：測試明明過了，你也按了同意，工作卻沒有完成。

因為在那兩件事之間，你又改了一行程式碼。通過測試的是舊的那一版，你同意的是新的那一版——票對不上。

ForgePilot 不會默默吞掉你的同意，也不會假裝沒事讓它過。它把審查記下來（那件事真的發生過），然後把兩個版本編號並排印給你看。

再跑一次驗證，兩邊對齊，就過了。

04

怎麼用：一天的形狀

全部是本機的命令列，沒有伺服器、沒有帳號、沒有網路。狀態存在你 repo 裡的一個 JSON 檔，被程序鎖保護著，多個終端機同時用也不會打架。

init

在 repo 裡建立狀態檔。它會動到 .gitignore，所以馬上 commit——之後每一步都要求工作樹是乾淨的。

goal / work add

宣告一個要跨多次工作才推得動的目標，然後把工作掛上去，順手寫清楚誰依賴誰。依賴沒完成的工作，一出生就是等待狀態，不需要你記得。

next

問它現在該做哪一件。這是純查詢，不會偷偷把工作認領給你，而且它會說出為什麼選中這一件。

start

開始。這時候你（或你的 agent）才真正去寫程式——ForgePilot 在這一段完全不插手。

verify

它在一個隔離的工作區裡，對確切的那個 commit 跑你自己專案的 make verify。看不到你還沒提交的東西，所以不會有「在我機器上是好的」。結果連同 commit 編號一起存起來。

gate

做到一半發現有件事不該自己決定？把問題和選項寫下來，工作就停在那裡等人。反射動作是開一道門，不是自己選一個繼續。

review

人看過之後同意或退回，理由留在檔案裡。四張票齊了就完成，同時解鎖下游；不齊就記下來並告訴你差什麼。

status

把所有東西攤開。沒有驗證、沒有審查都會被明講出來，不會用留白帶過——沉默的缺席會被讀成沒問題的結果。

05

它刻意不做的事

  • 不寫程式，也不取代你的 agent。寫程式的還是它們，ForgePilot 只決定哪件事現在可以動，以及它算不算完成。
  • 不發出任何網路請求。連你標註的 pull request 都不去查證——它只檢查格式，不假裝自己驗過了。
  • 不驗證身分。審查者的名字來自你的 git 設定，所以每次都明白印上「自稱」兩個字，免得誰把它當成簽章。
  • 完成之後不能反悔。DONE 是終點，沒有重開。要再動就開一件新工作，讓歷史留著。
  • 狀態是一個檔案。程序鎖加上原子替換，跨終端機、跨 session、關掉再開都讀得回同一份事實。
  • 驗證的內容由你定義。它只負責在乾淨且隔離的環境裡跑你的 make verify，然後如實記錄。
  • 記錄只增不改。通過、退回、被中斷的驗證全部並排留著，因為「測試沒過」跟「人不接受」是兩件不同的事。
  • 每個不易反轉的決定都寫成 ADR，附上它在什麼條件下會失效。你可以不同意，但不會找不到理由。
06

開始

需要 Go 1.25 以上。目前只宣稱支援 macOS 的本機檔案系統——程序鎖用的是作業系統的 flock，其他平台還沒實際驗證過，所以不亂講。

裝好之後，使用手冊會帶你從 init 一路走到 DONE，包含每一個會擋住你的地方——裡面所有輸出都是真的跑出來貼上去的，不是寫出來的範例。
