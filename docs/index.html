Engineering Control Plane

讓「做完了」這句話變貴

ForgePilot 不寫程式，也不取代你的 coding agent。證據不夠的時候，它不讓任何人宣告工作完成，包括 agent，也包括你自己。

01

用五歲小孩聽得懂的方式講一次

想像一條走廊，走到底就是「這件事做完了」。走廊上有四道關卡，每一關都要交出一樣東西才過得去，而那樣東西不能自己寫。

沒有這條走廊的時候，事情長這樣。你請一個很會寫程式的幫手做一件事，它做完跟你說「好了」。你問它測試過嗎，它說測過了。你信了，把它接到下一件事上。三天後你才發現，它測的是三個版本以前的程式碼。

它沒有騙人。「做完了」這句話誰都能說，說的時候不需要附上任何東西，所以它幾乎不用付出什麼。

ForgePilot 做的事，就是讓這句話說出口之前得先交出四樣東西。

它自己不寫程式，也不判斷程式碼好不好，那些是你和你的 agent 的事。它站在關卡旁邊清點東西，少了什麼就直接說出少的是什麼。

聽起來很煩。一個從來不擋人的流程，跟沒有流程差不多。

02

四道關卡，少一道就走不到底

有人真的看過並且同意

要有一筆明確記下來的人工審查，寫著誰在什麼時候同意了什麼。沒人反對不算同意。

Human Review

測試通過的，是你正在看的那一版

每次驗證都綁死一個 commit。之後只要再改一行，那次驗證就不算數了，工作重新卡住。

Evidence · exact revision

沒有懸著沒人決定的問題

遇到不該自己決定的事，開一道 Gate 把問題記下來。問題還開著，工作就過不去，而且誰都看得見它開著。

Gate

這個目標本身還在進行中

目標被暫停的時候，底下的工作連驗證都不給跑，直到有人把它解除。

Goal

四樣東西同時齊了，工作才進入 DONE。同一個瞬間，等著它的下一件工作變成可以開始，中間沒有「A 完成了但 B 還沒被通知」的空檔。

03

跟 agent 一起工作的時候，它站在哪裡

把寫程式的工作交給 agent 之後，有兩件事會同時發生。它做得比你快，而且它也比你更容易說出「做完了」。

它手上同時握著三個角色，自己挑要做哪一件事，自己寫，自己宣布完成。這三件事只要有一件出錯，你通常要等到很後面才會發現。

agent 可以寫程式，但不能發給自己通行證。

ForgePilot 把那三個角色拆開。哪一件事現在可以做，由佇列決定；程式碼由 agent 寫；算不算完成，由證據和人決定。agent 從頭到尾只被允許做中間那一段。

一次完整的迴圈長這樣。agent 從問「現在該做什麼」開始，到交出證據為止，中間有兩個地方它一定過不去。

這樣一來，agent 每次開工都得先問一次佇列，它拿到的是一件依賴已經清乾淨、確實輪到它的工作。做完之後它能做的最後一件事是跑驗證，把結果留下來。

你要看的東西也跟著變少。不必回頭審每一次對話，只要看 status 上有沒有卡住的工作，以及卡住的原因是哪一個。

同一份佇列可以同時給好幾個 agent 用。狀態檔有程序鎖，兩個 agent 不會同時認領到同一件工作。

怎麼把 agent 接上去

ForgePilot 沒有 agent 外掛，也不去攔截誰在跑什麼。它就是一個 CLI，所以接法是把規則寫進 agent 每次都會讀的那份指示檔，CLAUDE.md、AGENTS.md 或你的工具用的那一份都行。四條就夠了，規則本身建議用英文寫，指令與 flag 都是英文，混著中文敘述反而多一層轉換。

 貼進 AGENTS.md
## How work is picked up in this repo

1. Before starting anything, run `forgepilot next` and work only
   on the item it names. If it prints none, stop and ask a human.
   Never pick your own next task.
2. Claim it with `forgepilot start <work-id>`. Do not skip this.
3. Never report "done". When you believe the work is finished, run
   `forgepilot verify <work-id>` and paste the output verbatim.
   The evidence speaks for the work; your summary does not.
4. When a decision is not yours to make, run `forgepilot gate open`
   with the question and the options, then stop and wait. Never
   pick an option and carry on.

`review approve` is run by a human, never by you.

第四條最容易被忽略，它也是這套東西真正改變的地方。agent 卡住的時候原本會自己選一條路走下去，現在它把問題留在佇列上，你下次看 status 就會看到。

最後那句要說清楚它靠什麼成立。ForgePilot 不認證身分，agent 技術上跑得動 review approve，所以那是一句約定，不是一道鎖。真正擋著的是完成條件，agent 就算跑了 approve，只要 HEAD 跟通過驗證的 commit 對不上，或還有 Gate 開著，工作照樣不會進 DONE，而且那筆審查會用它的 git 身分留在記錄裡，跑不掉。

接下來的事跟你手動用一模一樣，安裝與 init 之後把上面四條貼進去就能開始。

04

被擋下來的時候，它會說出還差什麼

最容易讓人愣住的是這種情況。測試明明過了，你也按了同意，工作卻沒有完成。

因為在那兩件事之間，你又改了一行程式碼。通過測試的是舊的那一版，你同意的是新的那一版，兩邊對不上。

ForgePilot 不會默默吞掉你的同意，也不會假裝沒事讓它過。它把審查記下來，因為那件事真的發生過，然後把兩個版本編號並排印給你看。

再跑一次驗證，兩邊對齊，就過了。

forgepilot review approve WI-002

05

實際跑起來是什麼樣子

全部是本機的命令列，不需要伺服器，也不需要帳號。狀態存在你 repo 裡的一個 JSON 檔，由程序鎖保護，多個終端機同時用不會打架。

init

在 repo 裡建立狀態檔。它會動到 .gitignore，所以馬上 commit，因為之後每一步都要求工作樹是乾淨的。

goal / work add

宣告一個要跨多次工作才推得動的目標，把工作掛上去，順手寫清楚誰依賴誰。依賴還沒完成的工作，一建立就是等待狀態，不用你自己記。

next

問它現在該做哪一件。這是純查詢，不會偷偷把工作認領給你，而且它會說出為什麼選中這一件。

start

開始。這時候你或你的 agent 才真正去寫程式，ForgePilot 在這一段完全不插手。

verify

它在一個隔離的工作區裡，對確切的那個 commit 跑那個 repo 自己 Makefile 裡的 verify target。連 Makefile 存不存在都是在那份 checkout 裡判斷的，被 gitignore 掉的 Makefile 騙不過它。那個工作區也看不到你還沒提交的東西，所以不會有「在我機器上是好的」。結果連同 commit 編號一起存起來。

gate

做到一半發現有件事不該自己決定，就把問題和選項寫下來，工作停在那裡等人。它想養成的習慣就是這個，問題交出去，不要自己挑一個繼續做。

review

人看過之後同意或退回，理由留在檔案裡。四樣東西齊了就完成，同時解鎖下游；不齊就把審查記下來，並告訴你還差什麼。

status

把所有東西攤開。沒有驗證、沒有審查都會被明講出來，不會用留白帶過。沉默的缺席會被讀成沒問題的結果。

06

它刻意不做的事

  • 不寫程式，也不取代你的 agent。寫程式的還是它們，ForgePilot 只決定哪件事現在可以動，以及它算不算完成。
  • 不發出任何網路請求。連你標註的 pull request 都不去查證，它只檢查格式，不假裝自己驗過了。
  • 不驗證身分。審查者的名字來自你的 git 設定，所以每次都明白印上「自稱」兩個字，免得誰把它當成簽章。
  • 完成之後不能反悔。DONE 是終點，沒有重開。要再動就開一件新工作，把歷史留著。
  • 狀態是一個檔案。程序鎖加上原子替換，跨終端機、跨 session、關掉再開都讀得回同一份事實。
  • 驗證的內容由你定義。它固定跑 make verify，內容是那個 repo 自己 Makefile 寫的，ForgePilot 只負責在乾淨且隔離的環境裡執行並如實記錄。
  • 記錄只增不改。通過、退回、被中斷的驗證都並排留著，「測試沒過」跟「人不接受」是兩件不同的事。
  • 每個不易反轉的決定都寫成 ADR，附上它在什麼條件下會失效。你可以不同意，但不會找不到理由。
07

開始

需要 Go 1.25 以上。目前只宣稱支援 macOS 的本機檔案系統，因為程序鎖用的是作業系統的 flock，其他平台還沒實際驗證過。

裝好之後，使用手冊會帶你從 init 一路走到 DONE，包含每一個會擋住你的地方。裡面所有輸出都是真的跑出來貼上去的，不是寫出來的範例。
