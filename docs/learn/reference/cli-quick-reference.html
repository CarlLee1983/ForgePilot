ForgePilot CLI 快速參考

八組指令、五個持久化狀態，以及每一個會拒絕你的地方。指令以 forgepilot --help 與 CLI 契約 為準。

指令

指令參數結果
init—在目前 repository root 建立 .forgepilot/，並往 .gitignore 補上 entry。重複執行不覆寫。
goal import<plan-path>讀 Goal Plan（JSON），一次建立 Goal 與整張 DAG；節點 ID 即 Work Item ID。任何驗證失敗整份不寫入。重新匯入同一 Goal 只接受新增節點。
goal cancel<goal-id> --reasonACTIVE → CANCELLED，不再出現在 next。
next[--json]純查詢。只回傳一個建議動作與理由，不 start、不改狀態。--json 的每個欄位永遠存在。
start<work-id>READY → RUNNING。在寫交易內重查 Goal、依賴、Gate 與佔位。
verify<work-id> [--snapshot]先回收孤兒；無 flag 時在隔離 worktree 對乾淨 HEAD 跑 make verify，--snapshot 時對 immutable working-tree snapshot 執行，append Evidence。PASS 即 DONE（Goal 要求 Approval 時進 REVIEW）。
gate open--work --question --option --option [--reason]配發 GATE-nnn。至少兩個 --option。該工作即被阻擋。
gate resolve<gate-id> --option [--note] [--by]只接受列出的選項之一。轉為 RESOLVED。
gate cancel<gate-id> --reason [--by]轉為 CANCELLED 並解除阻擋——記錄「這個問題問錯了」。
review approve<work-id> [--note] [--by]僅適用要求 Approval 的 Goal。append APPROVED；條件成立則同交易進入 DONE 並解鎖下游。
review reject<work-id> --reason [--by]append REJECTED，REVIEW 工作退回 RUNNING。
status[--goal] [--work] [--json]每個 Goal 的節點：狀態、最新 Evidence、OPEN Gate、未完成的原因。

沒有的東西：done、complete <work-id>、任何 reopen、work add、reconcile、migrate、--pr。呼叫已移除的指令會回報 unknown command。

狀態

持久化的狀態只有五個：未開始（NOT_STARTED）、RUNNING、VERIFYING、REVIEW、DONE。PENDING 與 READY 是讀取時依「依賴是否全部 DONE」算出的投影，不保存。

PENDING ──依賴皆 DONE──▶ READY ──start──▶ RUNNING ──verify──▶ VERIFYING
                                             ▲                    │
                                             │ FAIL / INTERRUPTED │
                                             └────────────────────┤
                                                                  │ PASS
                          ┌── 要求 Approval ──────────────────────┤
                          ▼                                       ▼
                       REVIEW ──approve──▶ DONE ◀──不要求 Approval──┘
                          │                （終態）
                          ├──reject──▶ RUNNING
                          └──重新 verify──▶ VERIFYING

Gate 不在這張圖上。它是正交的維度：未解除的 Gate 擋住推進，但不改變狀態欄。

進入 DONE 的條件

預設的 Goal 在 verify PASS 的同一次交易內就是 DONE，並解鎖下游；全部節點 DONE 時 Goal 自動 COMPLETED。要求 Approval 的 Goal 則在 review approve 的同一次交易內檢查，全部成立才完成：

條件不成立時 status 會說
最新 Verification 為 PASS，且仍是目前的 Candidateapprove 被拒並要求重新 verify；next 建議 REVERIFY
該 Work Item 無未解除 Gateopen Gate GATE-n
其 Goal 為 ACTIVEgoal x is CANCELLED
stale 只對 REVIEW 有意義

REVIEW 工作的 PASS Evidence 綁定的 Candidate 不再符合目前 workspace（HEAD 變了，或 snapshot 的 digest 變了）時，approve 會被拒絕，必須重新 verify。DONE 是終態，不判 stale，也沒有 reopen。

它會拒絕你的地方

情況行為
工作樹不乾淨（含 untracked）不帶 flag 的 verify 拒絕並列出髒檔案；可用 verify <work-id> --snapshot 驗證 working tree。
受驗 revision 沒有 make verify target拒絕且不寫 Evidence——那是無法驗證，不是驗證失敗
已有一件 RUNNING 或 VERIFYINGstart 拒絕，錯誤指出佔位的工作：only one work item can be RUNNING or VERIFYING at a time
依賴未全部 DONEstart 拒絕：dependencies not DONE: a
Story 路徑不存在、不在 specs/stories/ 底下或逃出 repositorygoal import 整份拒絕，錯誤指出節點與欄位
Goal Plan 有環、未知／重複依賴、重複節點、未知 JSON 欄位goal import 整份拒絕
有未解除 Gate擋 start、擋 verify、不被 next 推薦、擋完成
Goal 非 ACTIVE擋開始新工作與擋完成，也不能再匯入；進行中的驗證跑完仍記錄 Evidence
對不要求 Approval 的 Goal 執行 review拒絕並說明原因
gate resolve 給了未列出的選項拒絕。選項全都不對時的正確動作是 cancel 再重開一個
review reject 沒給 --reason拒絕
state schema 版本不符拒讀。較舊者指向一次性匯出工具，較新者明說本 binary 不支援
沒設定 git config user.email 又沒給 --by拒絕，並指名該用哪個 flag
一個例外

被拒絕的 verify 在有孤兒時仍會寫入一筆 INTERRUPTED。中斷是已經發生的事實，不該被阻擋條件扣住；能不能再跑一次，才是阻擋條件要回答的問題。回收一定印在輸出上——會偷偷發生的才是問題（ADR-0009）。

身分

--by 省略時取自 git config user.email。所有輸出都會標示 self-asserted——這是聲明，不是認證，ForgePilot 不驗證任何人的身分（ADR-0005）。
