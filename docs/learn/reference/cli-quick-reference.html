ForgePilot CLI 快速參考

十個指令、六個狀態、四項完成條件，以及每一個會拒絕你的地方。以 internal/cli 的實際行為為準。

指令

指令參數結果
init—在目前 repository root 建立 .forgepilot/，並往 .gitignore 補上 entry。重複執行不覆寫。
migrate—備份為 state.json.v<n>.bak 後升級 schema。已是最新則回報並 exit 0。備份已存在時拒絕。
goal create--id --title [--description]建立 ACTIVE Goal。ID 由你指定。
goal block<goal-id> --reason轉為 BLOCKED。底下活躍工作維持原狀但無法推進。
goal unblock<goal-id>轉回 ACTIVE。
goal complete<goal-id>全部 Work Item 皆 DONE 才允許。人手動宣告，系統不推斷。
goal cancel<goal-id> --reason轉為 CANCELLED。
work add--goal --story [--depends-on ...]配發 WI-nnn。依賴皆 DONE 則 READY，否則 PENDING。
next—純查詢。不 claim、不 start、不改狀態。會說明選取理由。
start<work-id>READY → RUNNING。在寫交易內重查 Goal 與依賴。
verify<work-id>先回收孤兒，再在隔離 worktree 對 HEAD 跑 make verify，append Evidence。
gate open--work --question --option --option [--reason]配發 GATE-nnn。至少兩個 --option。該工作即被阻擋。
gate resolve<gate-id> --option [--note] [--by]只接受列出的選項之一。轉為 RESOLVED。
gate cancel<gate-id> --reason [--by]轉為 CANCELLED 並解除阻擋——記錄「這個問題問錯了」。
review approve<work-id> [--pr] [--note] [--by]append APPROVED；四項條件成立則同交易進入 DONE 並解鎖下游。
review reject<work-id> --reason [--pr] [--by]append REJECTED，工作退回 RUNNING。
status—整份佇列：狀態、最新 Evidence、OPEN Gate 數、未完成的原因。

沒有的東西：done、complete <work-id>、任何 reopen、Gate 查詢指令、--json、任意 status setter。

狀態

PENDING ──依賴皆 DONE──▶ READY ──start──▶ RUNNING ──verify──▶ VERIFYING
                                             ▲                    │
                                             │                    │ PASS
                          FAIL / INTERRUPTED └────────────────────┤
                                                                  ▼
                          reject ◀──────────────────────────── REVIEW ──四項條件──▶ DONE
                                                                  │                  （終態）
                                                                  └──重新 verify──▶ VERIFYING

Gate 不在這張圖上。它是正交的維度：未解除的 Gate 擋住推進，但不改變狀態欄。

進入 DONE 的四項條件

在 review approve 的同一次交易內檢查，全部成立才完成：

條件不成立時 status 會說
同一 revision 的最新 Verification 為 PASSthe latest verification EV-00n is FAIL 或 no verification evidence yet
最新 Human Review 為 APPROVEDno human review yet 或 the latest human review EV-00n is REJECTED
兩者綁在同一個 revision 上the latest PASS is at revision X but the approval is at Y
該 Work Item 無未解除 Gaten open gate(s)
其 Goal 為 ACTIVEgoal "x" is BLOCKED, not ACTIVE
最容易忘的一條

條件只在 review approve 執行的當下被評估。如果最後一個阻擋是在 approve 之後才解除的（你先 approve、再 resolve Gate），工作會停在 REVIEW，必須再跑一次 review approve。這是刻意的——核准者會先看到 Gate 被怎麼決定。status 會明講：Not complete, but every condition now holds。

它會拒絕你的地方

情況行為
工作樹不乾淨（含 untracked）verify 與 review 拒絕，不寫任何 Evidence
受驗 revision 沒有 make verify target拒絕且不寫 Evidence——那是無法驗證，不是驗證失敗
Story reference 不在 specs/stories/ 內或不存在work add 拒絕
有未解除 Gate擋 start、擋 verify、不被 next 選中、擋完成
Goal 非 ACTIVE擋開始新工作與擋完成，但進行中的驗證跑完仍記錄 Evidence
gate resolve 給了未列出的選項拒絕。選項全都不對時的正確動作是 cancel 再重開一個
review reject 沒給 --reason拒絕
--pr 不是 owner/name#number整個指令失敗且不寫入任何東西
state schema 版本不符拒讀。較舊者指示 migrate，較新者明說本 binary 不支援
沒設定 git config user.email 又沒給 --by拒絕，並指名該用哪個 flag
一個例外

被拒絕的 verify 在有孤兒時仍會寫入一筆 INTERRUPTED。中斷是已經發生的事實，不該被阻擋條件扣住；能不能再跑一次，才是阻擋條件要回答的問題。回收一定印在輸出上——會偷偷發生的才是問題（ADR-0009）。

身分

--by 省略時取自 git config user.email。所有輸出都會標示 self-asserted——這是聲明，不是認證，ForgePilot 不驗證任何人的身分（ADR-0005）。
