# Readiness is a projection made durable, and stale VERIFIED re-verification is owed, not immediate

`next` stays a pure query, so persisted PENDING readiness that outlived the Gate or stale Candidate which withdrew it needs an explicit writer: `forgepilot reconcile --goal <goal-id>` recomputes one ACTIVE Goal's PENDING/READY readiness from current repository facts, resolved inside the same locked state transaction, and refuses the whole command when a required fact cannot be read. It is a legal state transition, not a verification bypass: it reuses the one dependency-progression predicate, so it can promote exactly what a fresh `work add` would have made READY and nothing more — it appends no Evidence, answers no Gate, changes no review policy, and never touches RUNNING, VERIFYING, REVIEW, VERIFIED or DONE. READY remains orthogonal to blocking (ADR-0007): a reconciled Work Item with its own OPEN Gate still cannot start. `next` and `reconcile` share the predicate, so a recommendation is never one the command would report as unchanged.

Mid-queue progression and final acceptance are different questions and now have different schedules. Under `GOAL` policy every new Candidate makes earlier VERIFIED work stale, so ranking every stale VERIFIED ahead of startable work re-verifies the whole history between consecutive Work Items. START and RECONCILE candidates therefore share one creation-ordered pass ahead of GOAL-policy REVERIFY, while WORK_ITEM-policy stale REVIEW keeps its existing priority. This relaxes no freshness rule: the Goal final-review boundary in `internal/work/summary.go` still requires every Work Item's latest PASS to match the current Candidate, so each deferred re-verification is owed before the boundary rather than forgiven. Three chained Work Items on three revisions still cost five Verification Runs; no Evidence revision is rewritten, no PASS is shared between Work Items, and VERIFIED is still not DONE. No durable field was added — readiness was already stored, and the projection that recovers it is computed.

**Falsified if:** `internal/work/next.go` writes state or recommends RECONCILE for work `advanceable` would refuse, `internal/work/reconcile.go` changes a status other than PENDING/READY, appends Evidence, or treats an unresolved repository fact as fresh, `internal/cli/cli.go` resolves Candidate facts outside the locked transaction or reconciles a Goal that is not ACTIVE, or `internal/work/summary.go` stops requiring a current PASS for every Work Item at the Goal final-review boundary.
