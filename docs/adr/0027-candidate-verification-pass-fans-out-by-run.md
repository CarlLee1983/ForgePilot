# Candidate Verification 的 PASS 以一個 shared run fan-out

repository 的 canonical check 判斷的是一個 immutable Candidate 與該次 Resolved Runtime，而不是某一張 Work Item 私有的程式片段；同一 Goal 的 stale REVIEW／VERIFIED 工作逐張重跑同一個 global command，會製造多個其實沒有發生的 execution identities。`internal/app.Verify` 因此維持單一 caller interface，但 implementation 會以 anchor 為入口選出同 Goal、已有 PASS 且只因本次 Candidate 而 stale 的合法 cohort，只執行一個 canonical subprocess。PASS 在同一個 state transaction 內為 anchor 與 completion 時仍未改變、仍合法且 prerequisite-closed 的 recipients 各建立 Work Item-specific Evidence；每筆 Evidence 保留自己的 ID 與 Story association，同時共享一個 Verification Run ID、Candidate、Resolved Runtime、command、result、完成時間與 log identity。

fan-out 只適用 PASS。FAIL 與 INTERRUPTED 仍只記在 anchor，因為把一個 global failure 套到整批 stale VERIFIED 會把它們全部退回 RUNNING，讓 Runner 為同一個 failure 啟動多個 repair sessions；optional recipients 也因此不進 VERIFYING，crash reclaim 仍只有 anchor。另一張 RUNNING、PENDING、READY、VERIFYING、DONE、fresh item、OPEN Gate、非 ACTIVE Goal 與其他 Goal 都不會被順帶寫 Evidence。GOAL-policy recipient 可以用同 transaction 內也會取得 PASS 的 selected prerequisite 滿足 closure；WORK_ITEM-policy PASS 回到 RUNNING，不能當成 simultaneous prerequisite satisfaction。completion 若排除一個 changed recipient，必須重算 transitive closure 到 fixed point。

schema v9 為 active Run 與 Verification Evidence 加入 durable Verification Run ID。新 execution 使用 `VR-*`；v8 migration 對每筆舊 Verification Evidence 與 orphan Run 配發只供 legacy lookup 的 distinct `LVR-*`，Review Evidence 不得攜帶 run ID。這明確修正 ADR-0012：Evidence 仍不保存 `LogPath`，但 run ID 是有規則讀取的 execution provenance，也用來唯一找到新 run-keyed log；`LVR-*` 才沿用舊的 Work Item／revision lookup。新 log 必須 exclusive-create，lookup 使用完整 `runID + "-"` token boundary，不以裸 prefix 猜檔案。

existing per-Work-Item lock 仍包住 anchor 的完整 operation 並先回收 orphan；之後在任何 Candidate capture、checkout、runtime preflight、log、`CurrentRun` 或 canonical process 之前取得 repository-wide canonical-execution lock，直到 cleanup 結束才釋放。這個 coarse lock 是 global command 的 execution serialization，不是永久 cache：第二個 concurrent request 在沒有寫 state 或 artifacts 前被拒，之後明確重跑相同 Candidate 仍合法並取得新 run ID。Runner 仍只保存 execution history 與所有 returned Evidence IDs；cohort selection、atomic settlement 與 readiness refresh 全部留在 `internal/work`／`internal/app`，不複製到 Runner。

**Consequences:** 一個 Candidate 上的 Goal final-review Evidence set 仍是一張 Work Item 一個 exact Evidence ID，但它們可誠實指向同一個 Verification Run。PASS settlement 先驗證完整 surviving set、套用全部 Evidence/status，再以 completion transaction 內解析的 live repository facts refresh readiness；facts 失敗時 Evidence 保留、promotion fail closed。rollback 可把 cohort 收窄回 anchor-only，但 binary rollback 仍只能還原 schema migration 的 v8 backup，會遺失之後的 Evidence。

**Falsified if:** `internal/runner` 自行選 cohort 或逐張呼叫 lifecycle transition、optional RUNNING 工作因別張工作的 PASS 變成 VERIFIED、FAIL／INTERRUPTED fan-out 到 stale peers、同一 run ID 的 Verification Evidence 對 Candidate／runtime／command／result／timestamp 說法不同、PASS recipients 以多次 state save 落地、log lookup 以裸 run-ID prefix 猜檔案，或相同 Candidate 的後續明確 rerun被當成 cache hit 而拒絕執行。
