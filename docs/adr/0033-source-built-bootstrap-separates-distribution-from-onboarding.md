# Source-built Bootstrap separates distribution from Repository Onboarding

**Status relation:** This ADR supersedes only the coupled source-acquisition and target-onboarding portions of [ADR-0024](0024-onboarding-stays-outside-the-offline-cli.md) and [ADR-0030](0030-source-built-onboarding-without-apple-developer.md). It preserves their fixed-source, installed-Go, explicit-approval, offline-core boundaries; it does not revive the signed-binary path deferred by ADR-0025 or expand the Apple-Silicon-only support boundary in ADR-0032.

ForgePilot will add a repository-external POSIX-shell **Distribution Bootstrap** for Codex. It accepts only an absolute, developer-obtained local Git source checkout and a lowercase full 40-character `--commit`. Its inspection-only plan binds those facts and its separately approved execution creates a detached staging checkout, checks the already-installed compatible Go toolchain at that exact commit, source-builds, runs `make verify`, and proves the staged CLI starts. It then installs the CLI and Codex standalone skill as one recoverable **Bootstrap Transaction**. This keeps the source-built path usable repeatedly without making an unsigned binary or `curl | sh` a supported promise.

The user-owned root is `~/.local/share/forgepilot/`. A fully verified immutable generation contains the CLI, Codex skill, and its matching procedure. `current` is the sole authoritative generation pointer, protected by a Bootstrap lock and atomically replaced inside that root; the stable `~/.local/bin/forgepilot` and `~/.agents/skills/forgepilot-onboarding` links both resolve through it. Upgrade therefore does not rewrite either external link. A transaction record containing old and new generation identities is authoritative until current, previous, and manifest are reconciled under the lock. On the first installation, that record explicitly represents absent old identities and is persisted before either external link or `current` can be created; recovery can therefore finish only its recorded publication or remove only its recorded dangling links. The manifest, lock, transaction marker, and current/previous pointers are all contained in the managed root, are atomically written or recovered under the lock, and never make an unowned path eligible for deletion. Unknown entrypoints, skill paths, legacy manual adapters, manifest versions, drifted links, or unsafe layout fail closed.

Bootstrap owns only this user-home distribution state. Its controlled acquisition does not inspect or write a target repository, initialize `.forgepilot/`, alter a shell profile, install Go or a package manager, use remote source access, invoke credential helpers or Agent login, retain raw command output or environment values, or migrate state. It accepts no remote URL or scp source. Before approval it executes no source-controlled code. After approval, the declared source's build and `make verify` are intentionally executed and can have their own repository-defined effects; Bootstrap must isolate ambient Git routing, replacement objects, global/system Git config, credential helpers, askpass, and source checkout filters, but it cannot honestly claim to sandbox arbitrary approved build logic. **Repository Onboarding** remains a separately invoked process: the installed Codex skill receives an explicit absolute target and COMMIT or SNAPSHOT Candidate choice, performs target preflight and Story review, and obtains a distinct approval before any repository write. The existing short prompt remains the zero-install fallback.

**Consequences:** Implementation needs a versioned `forgepilot-bootstrap-plan-v1` action protocol, plan-bound approval that recomputes the plan from its original inputs, exclusive locking, revalidation immediately before every mutation, and crash-injection coverage for each generation publication, removal, and manifest boundary. It retains current and previous generations; any older generation persists until explicit `prune` or exact-commit `uninstall --commit`. V1 needs an unlocked, rechecked point-in-time `status` (macOS POSIX shell has no shared-lock primitive), an explicit-upgrade contract, and plan-bound manifest-proven removal of unprotected inactive generations; it deliberately does not provide a rollback command, full Bootstrap uninstall, or removal of current/previous. A clean native Apple-Silicon acceptance must demonstrate real Codex discovery of the managed symlink and the separate repository-write stop; test fakes do not prove that behavior.

**Falsified if:** Bootstrap becomes a command in `internal/cli`, `internal/app`, or `internal/repository`; it accepts a remote, branch, tag alias, abbreviated SHA, `latest`, inferred source identity, or ambient credential helper; it uses `curl | sh`, overwrites or deletes an unowned path, mutates a target repository, alters a shell profile, reads Agent credentials, or treats Agent output as Verification Evidence; or a crash/concurrent operation can expose CLI and Codex skill from different managed generations.
